# i로 로그인 플러그인 관리하기

> **Claude는 Console API 사용량에 따라 과금되며 Pro 또는 Max 요금제의 한도를 사용하지 않습니다.**
> API 키를 입력하지 않고 로그인해도 요청이 무료가 되는 것은 아닙니다. 승인하기 전에 Console 조직, 작업 공간, 결제 권한을 확인하세요.

`i`를 사용하여 연결 관리를 수행하고, 헬퍼 실행 파일 이름을 기억하거나 수동으로 연결 설정을 작성할 필요가 없습니다. 네이티브 로그인 플러그인은 운영체제 사용자 권한으로 실행됩니다. 이는 워크스페이스 WASM 도구 플러그인이 아니므로, 올바른 설치 패키지를 사용하십시오.

## 터미널에서 설정하기

`i`를 시작하고, 모델을 아직 구성하지 않았더라도 로컬 관리 명령을 입력합니다:

```text
/plugins
```

ChatGPT 또는 Claude를 선택하고, 권한을 확인한 후 플러그인을 설치하고 활성화합니다. `/login`을 입력하고, 로그인 플러그인을 선택한 다음 시스템 브라우저에서 승인합니다. 목록에서 모델을 선택하거나 사용할 수 있는 모델 ID를 입력합니다. 성공적으로 연결되면 `i`는 다음 작업에 대한 연결을 저장합니다. 또한 다음과 같은 명령어를 직접 입력할 수 있습니다:

```text
/plugins install chatgpt
/plugins enable chatgpt
/login chatgpt
```

메뉴를 닫기 위해 `/cancel` 명령어를 사용합니다. 작업이 실행되는 동안 플러그인이나 연결을 변경할 수 없습니다. 인증 및 모델 목록은 생성 요청을 보내지 않습니다. 연결 변경은 로그인 및 모델 선택이 모두 성공한 후에만 발생합니다. 오류 또는 취소는 이전 연결을 유지하고, `i`는 전환하기 전에 개인 설정 백업을 저장합니다.

## 명령줄에서 플러그인 관리하기

### 모델 및 추론 강도 변경

`/model`은 현재의 네이티브 연결 플러그인에서 모델 카탈로그를 읽습니다. 목록에서 숫자 하나를 선택하거나 모델 ID를 직접 입력합니다. 표준 API 키 연결은 카탈로그를 쿼리하지 않으므로, 모델 ID를 직접 입력해야 합니다. 이 기능은 다시 로그인하거나 계정을 전환하는 것이 아닙니다:

```text
/model
/model status
/model gpt-6.1-sol
/model gpt-6.1-sol high
/model effort high
/model effort auto
```

설정을 변경할 때는 작업, 승인 또는 대기 중인 항목이 없는 경우에만 변경해야 합니다. 설정은 연결마다 저장되며, 변경 전에 개인 백업을 수행합니다. 모델 목록을 취소하면 구성은 변경되지 않습니다. 모델만 변경하면 제공업체의 기본 설정으로 노력이 재설정되므로 다른 모델의 설정을 유지할 수 없습니다. `auto` 및 `default`는 노력을 명시하지 않습니다. 다른 값은 `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`입니다. 모든 모델이 모든 값을 지원하지 않으며, 카탈로그가 모든 기능을 광고하지 않을 수 있습니다. 설정을 변경하면 청구 가능한 요청이 전송되지 않습니다. 제공업체는 후속 요청에서 지원을 확인합니다. Responses API에서는 `reasoning.effort`를, Chat Completions API에서는 `reasoning_effort`를 사용합니다. Claude는 적응형 사고를 사용하여 `output_config.effort`를 사용합니다. `none`은 해당 모드를 지원하는 모델에서 사고를 비활성화하도록 요청합니다. 모든 모델이 더 높은 노력을 지원하거나 사고를 비활성화한다는 것을 가정하지 마십시오. [OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning) 및 [Claude effort](https://platform.claude.com/docs/en/build-with-claude/effort)를 참조하십시오.

```sh
i plugins list
i plugins install chatgpt
i plugins enable chatgpt
i login chatgpt
i plugins status chatgpt
i plugins models chatgpt
i plugins logout chatgpt
i plugins disable chatgpt
i plugins update chatgpt
i plugins reconnect chatgpt
i plugins remove chatgpt
```

`i plugins use chatgpt ACCOUNT_ID`를 사용하여 기존 계정으로 전환합니다. 기존 등록을 재인증하려면 `i login chatgpt --account ACCOUNT_ID`를 사용하거나, 특정 계정에서 로그아웃하려면 `i plugins logout chatgpt --account ACCOUNT_ID`를 사용합니다. 재인증은 이전 토큰을 복사하지 않고 등록을 진행합니다. 모델을 확인하기 전까지 현재 연결된 계정은 변경되지 않습니다.

`chatgpt` 대신 `claude`를 사용하면 Claude Console 플러그인을 관리할 수 있습니다. 설치하거나 업데이트하려면 확인이 필요합니다. 업데이트한 뒤에는 플러그인을 다시 활성화하고 로그인해야 기존 활성 연결이 사용자 모르게 바뀌지 않습니다. 보조 프로그램만 업데이트하고 기존 계정을 유지하려면 플러그인을 다시 활성화한 다음 `i plugins reconnect chatgpt`를 실행하세요. 계정과 모델 설정을 유지하면서 활성 연결을 검증된 새 실행 파일에 연결합니다. 다시 로그인하거나 생성 요청을 보내지 않습니다. 설치 중에는 `i`가 버전 조회, 다운로드한 바이트 수, 체크섬 검증과 저장 진행률을 표시합니다. 중단하려면 `/cancel`을 사용하세요. 연결 제한 시간은 10초이며, 다운로드당 최대 120초가 허용됩니다. 실패 시 자동으로 다시 시도하거나 플러그인을 활성화하지 않습니다. GitHub에서 다운로드할 때는 브라우저 설정이 아닌 터미널의 프록시 환경 변수를 사용합니다. 필요하면 `HTTPS_PROXY=http://127.0.0.1:3067 i`로 실행하되, 주소와 포트는 자신의 프록시 설정에 맞게 바꾸세요.

또한 `i` 내에서 프록시 규칙을 변경할 수도 있습니다. 기본적으로 규칙은 `~/.i/config/proxy.json` 파일에 사용자별로 저장되며 (`I_CONFIG_DIR`이 설정된 경우, 해당 디렉토리 아래에 저장됨), 워크스페이스에는 저장되지 않습니다:

```text
/proxy
/proxy 3067
/proxy :3067
/proxy 127.0.0.1:3067
/proxy socks5://127.0.0.1:3067
/proxy no
/proxy env
/proxy chatgpt 3067
/proxy claude no
/proxy plugins no
/proxy model 3067
/proxy chatgpt default
```

다음 순서대로 규칙이 적용됩니다: 목적별 규칙, 사용자 기본 설정, 그리고 원래 환경 또는 구성. 명시적인 `no`는 환경 프록시로 돌아가지 않습니다. 변경 사항은 이후 작업에만 영향을 미치며, 활성 요청을 중단하거나 재실행하지 않습니다. 브라우저와 이미 실행 중인 독립 서비스는 별도로 구성합니다. HTTP, HTTPS, SOCKS5, 그리고 SOCKS5h가 지원됩니다. 로컬 인증 콜백은 프록시를 사용하지 않습니다. 프록시 URL에는 사용자 이름, 비밀번호, 쿼리 또는 경로가 포함될 수 없으므로, 자격 증명이 명령 기록에 나타나지 않습니다. 이는 내장된 호스트 명령이며, 프록시 설정이나 계정 자격 증명을 WASM 플러그인에 노출하지 않습니다. 설치 선택을 제거하면 이전 패키지와 자격 증명이 유지되며 원격 인증을 취소하지 않습니다. 로그아웃하려면 플러그인을 비활성화하거나 제거하기 전에 `i plugins logout NAME`를 실행합니다. 원격 취소가 확인되지 않은 경우, 제공업체의 계정 설정을 확인하십시오.

설치 프로그램은 공식 GitHub 릴리스에서 일치하는 연결 파일을 다운로드합니다. GitHub에서 제공하는 SHA-256, ZIP 파일 목록, 대상 플랫폼을 확인한 다음, 각 실행 전에 실행 파일의 무결성을 확인합니다. 일치하는 플랫폼이 없으면, 제3자 설치 스크립트를 실행하는 대신 중단됩니다. 체크섬은 출판자의 신원을 확인하는 것이 아니라 파일의 무결성을 확인합니다. macOS **연결 패키지**는 개발자 ID로 서명되거나 노터라이즈되지 않았습니다. 플러그인 설치는 PATH를 변경하거나 관리자 권한이 필요하지 않습니다.

개발자는 `i plugins install chatgpt --package /absolute/path/package.zip`를 사용하여 로컬에서 빌드한 패키지를 테스트할 수 있습니다. 확인 후, 설치 프로그램은 여전히 아카이브 구성원과 대상 플랫폼을 확인합니다. 플러그인은 비활성화된 상태로 시작되며, 사용 전에 실행 파일의 무결성을 확인합니다. 로컬 패키지는 `local-build`로 표시되며, 공식 릴리스로 확인되지 않습니다. 신뢰할 수 있는 네이티브 코드만 설치하십시오. 브라우저 콜백 확인은 로그인 완료를 의미하지 않습니다. 터미널에서 토큰 교환, 신원 확인, 모델 선택이 완료될 때까지 기다리십시오.

오래된 사용자 레벨의 `desktop.json` 파일에는 여전히 `search` 및 `find_files`가 나열되어 있을 수 있으며, 이는 현재 기본 기능에 통합되었습니다. 로드 시, 호스트는 기존 기본 검색 항목을 제거하고 동일한 사용자 구성 디렉토리의 기존 기본 워커를 현재 실행 파일에 연결합니다. 파일 시스템에 파일을 변경하지 않고 사용자 정의 워커 및 플러그인에 대한 이름 충돌은 여전히 오류를 발생시킵니다. 호스트는 중복 확인을 건너뛰지 않습니다. 이러한 오류는 모델 요청 전에 발생하므로, 다시 로그인하는 것은 필요하지 않습니다.

### 생성 실패 진단

로컬 ChatGPT 연결은 Chat Completions이 아닌 `store:false` 및 `stream:true`를 사용하여 Responses API를 사용합니다. 터미널은 SSE를 선호하지만, `object:response`, 유효한 ID, `status:completed`, 유효한 출력이 있는 완전한 `application/json` Responses 객체를 수락합니다. `Content-Type` 헤더가 없는 경우, 본문에서 SSE 또는 JSON을 감지하고 동일한 유효성 검사를 적용합니다. 명시적으로 표시된 HTML 또는 지원되지 않는 기타 미디어 유형은 거부합니다. 오류 진단은 응답 본문이 아닌 형식 범주 및 바이트 수를 표시합니다. HTML, Chat Completions 객체, 유효하지 않은 JSON, 불완전한 도구 호출은 수락되지 않습니다. 응답 형식의 변경은 요청 재전송을 유발하지 않습니다. 로컬 웹 서비스는 유효한 SSE를 전송합니다. 콘텐츠 유형이 없거나 응답이 JSON인 경우, 브라우저에 유효한 SSE를 제공하기 전에 전체 응답을 유효성 검사합니다. 이 호환성 경로는 완료를 기다리고 자동으로 재전송하지 않습니다. 브라우저의 로컬 HTTP 400은 반드시 업스트림 상태를 의미하지 않습니다. 진단은 업스트림 HTTP 오류, 네트워크 오류, 형식 오류를 구분합니다.

실패 시, 진단 도구는 다음 단계 중 하나를 식별합니다: 요청 준비, 승인, HTTP, 응답 형식 또는 스트림 파싱. HTTP 진단 도구는 상태, 알려진 오류 코드 또는 매개변수 이름, 그리고 제한된 요청 ID만 표시합니다. 원시 오류, 프롬프트 또는 토큰을 표시하지 않습니다. 네트워크 또는 형식 오류는 로그인 상태를 유지하거나 계정, 모델 또는 API 키 결제 경로를 자동으로 전환하지 않습니다.

## 설정 및 자격 증명

- `<config_dir>/native-plugins.json` 파일에는 설치 경로, 해시 값, 활성화 상태가 저장되며, OAuth 토큰은 저장되지 않습니다.
- `<data_dir>/connections/accounts/NAME`는 플러그인의 인증 정보를 저장합니다. WASM 플러그인은 이러한 정보를 받지 않습니다.
- 로그인 메뉴는 모델 구성을 채웁니다. `chatgpt.json` 파일을 직접 작성할 필요가 없습니다.
- macOS와 Linux는 자체적인 디렉토리와 파일 권한을 사용합니다. Windows는 사용자 디렉토리의 ACL(Access Control List)을 상속받습니다.
- 이 애플리케이션은 사용자 자격 증명을 암호화하거나 시스템 키체인에 저장하지 않습니다. 동일한 사용자로 실행되는 악성 프로그램도 여전히 해당 자격 증명을 읽을 수 있습니다.

이 디렉토리를 워크스페이스, 공유 폴더, 버전 관리 시스템 또는 공개 백업에 저장하지 마십시오. 로그인 플러그인이 없어도 직접 API 키 연결은 계속 작동합니다.

## 브라우저와 페어링하기

플러그인을 설치하고 활성화한 후, 동일한 컴퓨터에서 다음 명령어를 실행하십시오:

```sh
i plugins serve chatgpt --origin https://i.lninl.com --port 0
```

Claude를 사용하는 경우 위 명령에서 `chatgpt` 대신 `claude`를 사용하세요. 터미널을 계속 실행하고 인쇄된 페어링 링크를 엽니다. 페이지에서 플러그인, 계정, 모델을 확인한 후 저장합니다. 페어링은 먼저 저장되지 않은 초안을 생성하고 기존 연결을 자동으로 대체하지 않습니다. 서비스를 재시작한 후 새 링크를 사용하십시오. 페어링 링크를 공유하지 마십시오. 각 링크에는 로컬 기능 비밀이 포함되어 있습니다.

이 서비스는 `127.0.0.1`만 수신하며, 지정된 페이지의 원본에 바인딩되며, 임의의 URL을 프록시하지 않습니다. 로컬 네트워크에 접근하는 HTTPS 페이지는 로컬 네트워크 권한이 필요할 수 있습니다. 브라우저 권한이나 CORS를 우회하지 않습니다. 스마트폰은 자체적으로 네이티브 플러그인을 실행할 수 없으며, 브라우저 연결을 삭제하면 네이티브 계정에서 로그아웃되지 않습니다.

## ChatGPT 제한 사항 및 문제 해결

이 플러그인은 공식 OAuth 동적 클라이언트 등록, PKCE, 별도의 호스트 식별, 그리고 별도의 인증 정보 저장 기능을 사용합니다. 사용자의 개인 `~/.codex/auth.json` 파일을 읽거나, 독점적인 클라이언트 ID를 사용하지 않습니다. [공식 로그인 문서](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) 및 [프로필 및 세션](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)을 참조하십시오.

Inference는 공개된 Responses API를 사용하며, `backend-api`를 사용하지 않습니다. OpenAI는 자격, 워크스페이스 정책, 권한 제한을 결정합니다. 로그인은 Inference 접근을 보장하지 않습니다. 구독 기반 권한 설정은 `store: false` 및 `stream: true`와 같은 고정 설정을 사용합니다. 현재 프리뷰는 최대 출력 토큰 설정을 무시합니다. 자세한 내용은 [프리뷰 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)을 참조하십시오.

인증 코드 교환, 세션 갱신, 네트워크 오류 등이 실패로 이어집니다. 진단 결과는 HTTP 상태 코드를 표시하지만, 원본 토큰 엔드포인트 응답, 자격 증명, 인증 코드를 표시하지 않습니다. 실패한 인증 또는 모델 요청은 자동으로 다시 시도되지 않습니다. 코드 교환이 거부되면, 다시 로그인하고 버전, 시스템 시간, 네트워크, 프록시 설정을 확인하십시오. 상태 코드는 혼자서는 왜 거부되었는지 알려주지 않습니다.

## Claude Console 제한 사항

[공식 설치 가이드](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/quickstart)를 참조하여 `ant`를 설치하고, PATH에 제대로 설정되었는지 확인하십시오. 연결 패키지는 `ant`를 포함하거나 설치 스크립트를 자동으로 실행하지 않습니다. 그런 다음 `i login claude`를 사용하십시오.

이 플러그인은 격리된 HOME, `ANTHROPIC_CONFIG_DIR`, 그리고 자체 프로필을 사용합니다. 기존의 Claude Code 또는 개인별 Ant 프로필을 읽지 않습니다. 현재는 하나의 콘솔 프로필만 지원합니다. 재인증을 통해 워크스페이스를 변경할 수 있으며, 이후 요청은 새로운 워크스페이스를 사용할 수 있습니다. 필요한 경우 새 세션을 시작하십시오. **Claude는 Console API 사용량에 따라 과금되며 Pro 또는 Max 요금제의 한도를 사용하지 않습니다.**

## 검증 범위

자동화된 테스트는 격리된 디렉토리와 로컬 OAuth/TLS 환경을 사용합니다. 실제 개인 토큰을 사용하거나, 귀하를 대신하여 접근 권한을 부여하거나, 청구 가능한 요청을 보내지 않습니다. 오프라인 테스트를 통과하는 것은 특정 제공업체가 실제 계정에 대한 접근 권한을 부여할 것이라는 것을 증명하지 않습니다. 헬퍼는 자체적인 워커 및 서비스 프로토콜을 유지하며, 사용자 인터페이스를 통해 `i`를 거쳐 작업을 수행합니다.
