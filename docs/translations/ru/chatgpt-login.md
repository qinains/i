# Управление плагинами входа с помощью i

> **Использование Claude оплачивается через Console API, а не за счёт лимита подписки Pro или Max.**
> Вход без указания ключа API не делает запросы бесплатными. Перед авторизацией проверьте организацию, рабочее пространство и разрешения на оплату в Console.

Используйте `i` для управления подключениями, не запоминая имена исполняемых файлов или вводя настройки подключения вручную. Встроенные плагины для входа работают с правами пользователя вашей операционной системы. Они не являются плагинами WASM для рабочего пространства; используйте правильный пакет установки.

## Настройка в терминале

Начните с `i` и введите команду локального управления, даже если вы еще не настроили модель:

```text
/plugins
```

Выберите ChatGPT или Claude, просмотрите настройки разрешений, затем установите и включите плагин. Введите `/login`, выберите плагин для входа и авторизуйте его в браузере вашей системы. Выберите модель из списка или введите идентификатор модели, который вы хотите использовать. После успешного выполнения, `i` сохранит соединение для вашей следующей задачи. Вы также можете вводить команды напрямую:

```text
/plugins install chatgpt
/plugins enable chatgpt
/login chatgpt
```

Используйте `/cancel`, чтобы закрыть меню. Вы не можете изменять плагины или соединения, пока выполняется задача. Запрос авторизации и списка моделей не отправляет запросы на генерацию. Изменение соединения происходит только после успешной авторизации и выбора модели. Ошибки и отмены оставляют предыдущее соединение нетронутым, а `i` сохраняет резервную копию приватной конфигурации перед переключением.

## Управление плагинами из командной строки

### Смена модели и уровня рассуждения

`/model` считывает каталог моделей из текущего плагина подключения. Выберите номер из списка или введите идентификатор модели непосредственно. Стандартные подключения с использованием API-ключа не запрашивают каталог; введите идентификатор модели самостоятельно. Это не требует повторного входа или смены учетной записи:

```text
/model
/model status
/model gpt-6.1-sol
/model gpt-6.1-sol high
/model effort high
/model effort auto
```

Изменяйте настройки только в том случае, если нет незавершенных задач, утверждений или элементов в очереди. Настройки сохраняются для каждого подключения, с созданием резервной копии перед записью. Отмена списка моделей не изменяет конфигурацию. Переключение только одной модели сбрасывает усилия до значения по умолчанию, поэтому настройки другой модели не будут перенесены. Значения `auto` и `default` оставляют усилия без указания. Другие значения: `none`, `minimal`, `low`, `medium`, `high`, `xhigh` и `max`. Не все модели поддерживают все значения, и каталог может не указывать на их возможности. Изменение настройки не отправляет запрос на генерацию, за который взимается плата. Предоставитель проверяет поддержку при последующих запросах. В Responses API используется `reasoning.effort`, а в Chat Completions API — `reasoning_effort`. Claude использует `output_config.effort` с адаптивным мышлением. Значение `none` указывает на то, что мышление следует отключить для моделей, которые поддерживают этот режим. Не предполагайте, что все модели поддерживают более высокие усилия или отключение мышления. Обратитесь к [OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning) и [Claude effort](https://platform.claude.com/docs/en/build-with-claude/effort).

```sh
i plugins list
i plugins install chatgpt
i plugins enable chatgpt
i login chatgpt
i plugins status chatgpt
i plugins models chatgpt
i plugins logout chatgpt
i plugins disable chatgpt
i plugins update chatgpt
i plugins reconnect chatgpt
i plugins remove chatgpt
```

Переключитесь на существующий аккаунт, используя команду `i plugins use chatgpt ACCOUNT_ID`. Используйте `i login chatgpt --account ACCOUNT_ID` для повторной авторизации существующей регистрации, или `i plugins logout chatgpt --account ACCOUNT_ID` для выхода из конкретного аккаунта. Повторная авторизация позволяет зарегистрироваться, не копируя старые временные токены. Она не изменяет аккаунт в текущем соединении до тех пор, пока вы не подтвердите модель.

Чтобы управлять плагином Claude Console, используйте `claude` вместо `chatgpt`. Установка и обновления требуют подтверждения. После обновления снова включите плагин и войдите, чтобы избежать скрытой замены активного соединения. Если вы обновляете только помощника и хотите сохранить существующий аккаунт, снова включите плагин и выполните команду `i plugins reconnect chatgpt`. Это сохранит текущий аккаунт и настройки модели, а также свяжет активное соединение с проверенным новым исполняемым файлом. Это не требует повторного входа или отправки запроса на генерацию. Во время установки `i` показывает поиск версии, скачанные байты, проверку контрольной суммы и сохранение прогресса. Используйте `/cancel`, чтобы остановить. Соединение прекращается через 10 секунд, и каждый запрос может занимать до 120 секунд. Ошибки не вызывают автоматической повторной попытки или активацию плагина. Загрузка с GitHub использует переменные среды прокси терминала, а не настройки прокси вашего браузера. Если необходимо, начните с `HTTPS_PROXY=http://127.0.0.1:3067 i`, заменив адрес и порт на ваши собственные настройки прокси.

Вы также можете изменять правила прокси непосредственно в `i`. По умолчанию, правила сохраняются для каждого пользователя в файле `~/.i/config/proxy.json` (в каталоге `I_CONFIG_DIR`, если он определен), а не в рабочем пространстве.

```text
/proxy
/proxy 3067
/proxy :3067
/proxy 127.0.0.1:3067
/proxy socks5://127.0.0.1:3067
/proxy no
/proxy env
/proxy chatgpt 3067
/proxy claude no
/proxy plugins no
/proxy model 3067
/proxy chatgpt default
```

Правила действуют в следующем порядке: правило для конкретной цели, настройки по умолчанию пользователя, затем исходная среда или конфигурация. Явное указание `no` никогда не возвращается к среде прокси. Изменения затрагивают только последующие операции; они не прерывают или повторяют активные запросы. Настройте браузеры и уже запущенные автономные сервисы отдельно. Поддерживаются HTTP, HTTPS, SOCKS5 и SOCKS5h. Локальные вызовы обратного вызова не используют прокси. URL-адреса прокси не могут содержать имена пользователей, пароли, запросы или пути, поэтому учетные данные не попадают в историю команд. Это встроенная команда хоста; она не раскрывает настройки прокси или учетные данные для плагинов WASM рабочего пространства. Удаление выбранного варианта установки сохраняет старые пакеты и учетные данные и не отменяет удаленное авторизование. Чтобы выйти, запустите `i plugins logout NAME` перед отключением или удалением плагина. Если удаленное отмену не подтверждено, проверьте настройки учетной записи у поставщика.

Установщик скачивает соответствующий файл подключения из официального репозитория GitHub Releases. Он проверяет SHA-256, предоставленный GitHub, список разрешенных ZIP-архивов и целевую платформу, а затем проверяет целостность исполняемого файла перед каждым запуском. Если целевая платформа не найдена, установщик прекращает работу, вместо того чтобы запускать сторонние скрипты установки. Проверка контрольной суммы не подтверждает личность разработчика, а только целостность файла. Пакеты подключения для macOS не подписаны Developer ID и не прошли процедуру нотификации. Установка плагина не изменяет переменную PATH и не требует прав администратора.

Разработчики могут протестировать локально собранный пакет, используя `i plugins install chatgpt --package /absolute/path/package.zip`. После подтверждения установщик все равно проверяет содержимое архива и целевую платформу. Плагин запускается в отключенном состоянии, и его исполняемый файл проверяется перед использованием. Локальный пакет имеет метку `local-build` и не считается официальным релизом. Устанавливайте только код, которому вы доверяете. Подтверждение обратного вызова браузера не означает, что вход завершен. Подождите, пока терминал завершит обмен токенами, проверку личности и выбор модели.

Более старые файлы `desktop.json` на уровне пользователя могут по-прежнему содержать записи `search` и `find_files`, которые теперь являются частью основной функциональности. При загрузке, хост удаляет известные старые встроенные элементы поиска и связывает старых встроенных рабочих процессы из той же директории конфигурации пользователя с текущим исполняемым файлом, не изменяя файл на диске. Конфликты имен для пользовательских рабочих процессов и плагинов все еще приводят к ошибкам; хост не пропускает проверки дубликатов. Эти ошибки возникают до запросов модели, поэтому повторный вход не требуется.

### Диагностика сбоев генерации

Локальные подключения к ChatGPT используют API Responses с параметрами `store:false` и `stream:true`, а не объекты Chat Completions. Терминал предпочитает SSE, но также принимает полный объект `application/json` Responses, если он содержит `object:response`, действительный ID, `status:completed` и допустимый вывод. Без заголовка `Content-Type`, он обнаруживает SSE или JSON из тела и затем применяет ту же проверку. Он явно отклоняет HTML или другие не поддерживаемые типы медиа. Диагностика ошибок показывает только категорию формата и количество байт, а не содержимое ответа. Не принимаются HTML, объекты Chat Completions, недействительный JSON и неполные вызовы инструментов. Изменение формата ответа не приводит к повторной отправке запроса. Локальный веб-сервис пересылает действительный SSE. Если тип содержимого отсутствует или ответ в формате JSON, он проверяет полный ответ перед предоставлением действительного SSE браузеру. Этот путь совместимости ожидает завершения и не отправляет запрос автоматически. Локальный HTTP 400 в браузере не обязательно означает ошибку на стороне сервера: диагностика различает ошибки HTTP на стороне сервера, сбои сети и ошибки формата.

В случае возникновения ошибки, диагностика определяет стадию: подготовка запроса, авторизация, HTTP, формат ответа или разбор потока. Диагностика HTTP включает только статус, известные коды ошибок или имена параметров, а также ограниченный идентификатор запроса. Она не отображает исходные ошибки, подсказки или токены. Ошибки сети или формата не отменяют вашу авторизацию или автоматически не переключают аккаунты, модели или пути выставления счетов API-ключа.

## Настройки и учётные данные

- `<config_dir>/native-plugins.json` содержит путь установки, хеш и состояние, в котором плагин включен, а не токены OAuth.
- `<data_dir>/connections/accounts/NAME` хранит учетные данные плагина; плагины WASM для рабочего пространства их не получают.
- Меню входа автоматически заполняет конфигурацию модели. Вам не нужно писать файл `chatgpt.json`.
- macOS и Linux используют приватные каталоги и права доступа к файлам. Windows наследует ACL (контроль доступа) для пользовательских каталогов.
- Приложение не шифрует учетные данные и не хранит их в системном ключе. Злонамеренные программы, работающие от имени того же пользователя, все равно могут их прочитать.

Не храните эти директории в рабочих пространствах, общих папках, системах контроля версий или в публичных резервных копиях. Прямые подключения API-ключа продолжают работать без плагина для входа.

## Сопряжение с браузером

После установки и включения плагина, выполните следующие действия на той же машине, где работает браузер:

```sh
i plugins serve chatgpt --origin https://i.lninl.com --port 0
```

Для Claude в приведённой выше команде используйте `claude` вместо `chatgpt`. Оставьте терминал открытым и откройте распечатанную ссылку для сопряжения. Подтвердите плагин, аккаунт и модель на странице, а затем сохраните. Сопряжение сначала создает незаполненный черновик и не автоматически заменяет существующее соединение. Используйте новую ссылку после перезапуска сервиса. Не распространяйте ссылки для сопряжения: каждая из них содержит локальный секретный ключ.

Сервис работает только по адресу `127.0.0.1`, привязан к указанному источнику страницы и не обрабатывает произвольные URL-адреса. Для доступа к HTTPS-страницам, использующим обратный адрес, может потребоваться разрешение для локальной сети. Подключение не обходит разрешения браузера или CORS. Телефон не может самостоятельно запускать нативный плагин, а удаление подключения к браузеру не приводит к выходу из нативного аккаунта.

## Ограничения ChatGPT и устранение неполадок

Плагин использует официальную динамическую регистрацию клиента OAuth, PKCE, отдельную идентификацию хоста и отдельное хранилище учетных данных. Он не читает ваш личный файл `~/.codex/auth.json` или использует собственные идентификаторы клиентов. Обратитесь к [официальной документации по входу](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) и [профилям и сессиям](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).

Функция "Inference" использует публичный API Responses, а не приватный `backend-api`. OpenAI определяет условия использования, политику рабочего пространства и ограничения доступа; вход в систему не гарантирует доступ к "Inference". Авторизация на основе подписки использует фиксированные настройки `store: false` и `stream: true`. Текущая предварительная версия игнорирует настройку максимального количества токенов вывода; подробности смотрите в разделе [ограничения предварительной версии](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Ошибки возникают при обмене кодами авторизации, обновлении сеанса и сетевых ошибках. Диагностика показывает коды HTTP-статуса, но не отображает исходные ответы от конечных точек токенов, учетные данные или коды авторизации. Неудачная авторизация или запросы модели не автоматически повторяются. Если обмен кодом был отклонен, попробуйте повторно войти и проверьте версию, системное время, сетевые настройки и настройки прокси. Сам код статуса не объясняет, почему он был отклонен.

## Ограничения Claude Console

Следуйте [официальной инструкции по установке](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/quickstart), чтобы установить `ant` и убедиться, что он находится в переменной окружения PATH. Пакет подключения не содержит `ant` и не запускает его скрипт установки автоматически. Затем используйте команду `i login claude`.

Плагин использует изолированное окружение HOME, `ANTHROPIC_CONFIG_DIR`, и свой собственный профиль. Он не читает существующие профили Claude Code или личные профили. В настоящее время он поддерживает один профиль консоли. Переавторизация может изменить рабочее пространство, и последующие запросы могут использовать новое рабочее пространство; при необходимости, начните новую сессию. **Использование Claude оплачивается через Console API, а не за счёт лимита подписки Pro или Max.**

## Область проверки

Автоматизированные тесты используют изолированные каталоги и локальные фиктивные OAuth/TLS. Они не используют реальные личные токены, не авторизуют доступ от вашего имени и не отправляют запросы, за которые взимается плата. Успешное прохождение тестов в автономном режиме не доказывает, что поставщик предоставит доступ к реальному аккаунту. Вспомогательные функции сохраняют свои внутренние протоколы работы с сотрудниками и сервисами; операции, видимые пользователю, проходят через `i`.
