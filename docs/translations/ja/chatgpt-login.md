# i でログインプラグインを管理する

> **Claude は Console API の利用料金で請求され、Pro / Max の利用枠は使いません。**
> API キーを入力せずにログインできても、リクエストは無料にはなりません。承認する前に、Console の組織、ワークスペース、請求権限を確認してください。

`i` を使用して、ヘルパー実行ファイルの名前を覚えたり、手動で接続設定を書いたりすることなく、接続を管理できます。ネイティブのサインインプラグインは、オペレーティングシステムのユーザー権限で動作します。これらは、ワークスペースの WASM ツールプラグインではなく、正しいインストールパッケージを使用してください。

## ターミナルで設定する

`i` で開始し、ローカル管理コマンドを入力してください。まだモデルを設定していない場合でも構いません。

```text
/plugins
```

ChatGPT または Claude を選択し、権限を確認した後、プラグインをインストールして有効にします。 `/login` と入力し、サインインプラグインを選択し、システムブラウザで認証します。リストからモデルを選択するか、使用可能なモデル ID を入力します。 成功した場合、`i` は次のタスク用の接続を保存します。 また、コマンドを直接入力することもできます:

```text
/plugins install chatgpt
/plugins enable chatgpt
/login chatgpt
```

メニューを閉じるには `/cancel` を使用します。タスクが実行されている間、プラグインや接続を変更することはできません。認証とモデルのリスト表示は、生成リクエストを送信しません。接続の変更は、ログインとモデルの選択が成功した後に行われます。エラーやキャンセルは、前の接続を維持し、`i` は切り替える前にプライベートな設定のバックアップを保存します。

## コマンドラインでプラグインを管理する

### モデルと推論の強度を変更する

`/model` は、現在のネイティブ接続プラグインからモデルカタログを読み取ります。リストから番号を選択するか、モデルIDを直接入力します。標準のAPIキー接続では、カタログをクエリしません。モデルIDを手動で入力する必要があります。これにより、再度ログインしたり、アカウントを切り替える必要はありません。

```text
/model
/model status
/model gpt-6.1-sol
/model gpt-6.1-sol high
/model effort high
/model effort auto
```

設定を変更する際は、未完了のタスク、承認、またはキューされたアイテムがない場合にのみ行ってください。設定は接続ごとに保存され、書き込み前にプライベートなバックアップが作成されます。モデルリストをキャンセルすると、設定は変更されません。モデルのみを変更すると、設定はプロバイダーのデフォルトに戻ります。これにより、別のモデルの設定を保持することなく、設定をリセットできます。`auto` および `default` は、努力に関する情報を明示しません。その他の値は `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、および `max` です。すべてのモデルがすべての値をサポートしているわけではなく、カタログがその機能を宣伝しているとは限りません。設定を変更すると、請求可能な生成リクエストは送信されません。プロバイダーは、その後のリクエストでサポートを確認します。Responses API では `reasoning.effort`、Chat Completions API では `reasoning_effort` を使用します。 Claude では、適応的な思考と組み合わせて `output_config.effort` を使用します。`none` は、そのモードをサポートするモデルで思考を無効化するように要求します。すべてのモデルがより高い努力をサポートするか、思考を無効化することを前提にしないでください。OpenAI の [reasoning](https://developers.openai.com/api/docs/guides/reasoning) および Claude の [effort](https://platform.claude.com/docs/en/build-with-claude/effort) を参照してください。

```sh
i plugins list
i plugins install chatgpt
i plugins enable chatgpt
i login chatgpt
i plugins status chatgpt
i plugins models chatgpt
i plugins logout chatgpt
i plugins disable chatgpt
i plugins update chatgpt
i plugins reconnect chatgpt
i plugins remove chatgpt
```

`i plugins use chatgpt ACCOUNT_ID` を使用して、既存のアカウントに切り替えます。既存の登録を再認証するには、`i login chatgpt --account ACCOUNT_ID` を使用します。特定の口座からログアウトするには、`i plugins logout chatgpt --account ACCOUNT_ID` を使用します。再認証は、古いトークンをコピーすることなく登録を完了します。モデルを確認するまで、現在の接続のままアカウントは変更されません。

Claude Console プラグインを管理するには、`chatgpt` の代わりに `claude` を使用します。 インストールとアップデートには確認が必要です。 アップデート後、プラグインを再度有効にし、ログインして、アクティブな接続を無効にしないようにしてください。 ヘルパーのみをアップデートし、同じアカウントを維持したい場合は、プラグインを再度有効にし、`i plugins reconnect chatgpt` を実行してください。 これにより、現在のアカウントとモデル設定を維持し、検証済みの新しい実行ファイルにアクティブな接続をバインドします。 ログインしたり、生成リクエストを送信したりしません。 インストール中に、`i` はバージョン確認、ダウンロードされたバイト数、チェックサム検証、および進捗の保存を表示します。 停止するには `/cancel` を使用します。 接続は 10 秒後にタイムアウトし、各ダウンロードには最大 120 秒かかる場合があります。 失敗は自動再試行やプラグインの有効化をトリガーしません。 GitHub からのダウンロードでは、ブラウザの設定ではなく、ターミナルのプロキシ環境変数が使用されます。 必要に応じて、`HTTPS_PROXY=http://127.0.0.1:3067 i` を使用して、アドレスとポートを自分のプロキシ設定に置き換えてください。

また、`i` 内からプロキシ設定を変更することも可能です。デフォルトでは、設定はユーザーごとに `~/.i/config/proxy.json` ( `I_CONFIG_DIR` が設定されている場合はそのディレクトリの下) に保存され、ワークスペースには保存されません。

```text
/proxy
/proxy 3067
/proxy :3067
/proxy 127.0.0.1:3067
/proxy socks5://127.0.0.1:3067
/proxy no
/proxy env
/proxy chatgpt 3067
/proxy claude no
/proxy plugins no
/proxy model 3067
/proxy chatgpt default
```

以下の順序でルールが適用されます: 目的別のルール、ユーザーのデフォルト設定、そして元の環境または設定。明示的な `no` は、決して環境プロキシにフォールバックしません。変更は、後続の操作のみに影響します。アクティブなリクエストを中断したり、再実行したりしません。ブラウザと、すでに実行されているスタンドアロンサービスを個別に構成します。HTTP、HTTPS、SOCKS5、および SOCKS5h がサポートされています。ローカルの認証コールバックはプロキシを使用しません。プロキシ URL には、ユーザー名、パスワード、クエリ、またはパスを含めることができません。そのため、認証情報はコマンド履歴に保存されません。これは組み込みのホストコマンドであり、ワークスペースの WASM プラグインにプロキシ設定やアカウントの認証情報を公開しません。インストール選択を削除すると、古いパッケージと認証情報が保持され、リモート認証は無効化されません。ログアウトするには、プラグインを無効化または削除する前に `i plugins logout NAME` を実行します。リモートでの無効化が確認されない場合は、プロバイダーのアカウント設定を確認してください。

インストーラは、公式のGitHub Releaseから対応する接続アタッチメントをダウンロードします。GitHubによって提供されたSHA-256、ZIPメンバーの許可リスト、およびターゲットプラットフォームを確認し、各実行前に実行ファイルの整合性を検証します。プラットフォームが一致しない場合は、サードパーティのインストールスクリプトを実行するのではなく、停止します。チェックサムは、発行者の身元ではなく、整合性を検証します。macOSの**接続パッケージ**は、開発者IDで署名またはノータライズされていません。プラグインのインストールは、PATHを変更したり、管理者権限を必要としません。

開発者は、`i plugins install chatgpt --package /absolute/path/package.zip`を使用してローカルで作成したパッケージをテストできます。確認後、インストーラはアーカイブのメンバーとターゲットプラットフォームを再度チェックします。プラグインは無効状態で起動し、使用前に実行ファイルの整合性を確認します。ローカルパッケージは`local-build`という名前で、公式リリースとして検証されていません。信頼できるネイティブコードのみをインストールしてください。ブラウザからのコールバック確認は、ログインが完了したことを意味しません。ターミナルがトークンの交換、本人確認、およびモデル選択を完了するまで待ってください。

古いユーザーレベルの `desktop.json` ファイルには、現在コア機能として組み込まれている `search` と `find_files` がまだリストされている場合があります。 起動時に、ホストは認識可能な古い組み込み検索エントリを削除し、同じユーザー設定ディレクトリにある古い組み込みワーカーを現在の実行ファイルにバインドしますが、ディスク上のファイルは変更しません。 カスタムワーカーとプラグインの競合する名前は、依然としてエラーを引き起こします。 ホストは重複チェックをスキップしません。 これらのエラーはモデルの要求の前に発生するため、再度ログインする必要はありません。

### 生成に失敗したときの診断

ローカルの ChatGPT 接続では、`store:false` と `stream:true` を使用した Responses API を使用し、Chat Completions ではありません。ターミナルは SSE を優先しますが、`object:response`、有効な ID、`status:completed`、および有効な出力がある場合は、完全な `application/json` Responses オブジェクトも受け入れます。 `Content-Type` ヘッダーがない場合、本文から SSE または JSON を検出し、同じ検証を適用します。 明示的にマークされた HTML やその他のサポートされていないメディアタイプは拒否されます。 失敗診断では、応答本文ではなく、形式カテゴリとバイト数をのみ表示します。 HTML、Chat Completions オブジェクト、無効な JSON、および不完全なツール呼び出しは受け入れられません。 応答形式の変更は、リクエストの再送信を引き起こしません。 ローカルの Web サービスは、有効な SSE をライブで転送します。 コンテンツタイプが欠けている場合、または応答が JSON の場合、ブラウザに有効な SSE を提供する前に、完全な応答を検証します。 この互換性パスは、完了を待って自動的に再送信しません。 ブラウザのローカル HTTP 400 は、必ずしも上流のステータスとは限りません。 診断では、上流の HTTP エラー、ネットワーク障害、および形式障害を区別します。

エラーが発生した場合、診断機能は問題の段階を特定します：リクエストの準備、認証、HTTP、レスポンス形式、またはストリームの解析。HTTP診断機能には、ステータス、既知のエラーコード、またはパラメータ名、および限定的なリクエストIDのみが含まれます。生のエラー、プロンプト、またはトークンは表示されません。ネットワークまたは形式のエラーは、ログインを解除したり、アカウント、モデル、またはAPIキーの課金パスを自動的に切り替えることはありません。

## 設定と認証情報

- `<config_dir>/native-plugins.json` には、インストールパス、ハッシュ値、および有効な状態が保存されており、OAuth トークンは保存されていません。
- `<data_dir>/connections/accounts/NAME` にはプラグインの認証情報が保存されます。ただし、ワークスペース用の WASM プラグインには、これらの認証情報は提供されません。
- サインインメニューでモデルの構成を指定します。`chatgpt.json` を手動で作成する必要はありません。
- macOS と Linux は、プライベートなディレクトリとファイル権限を使用します。Windows は、ユーザーディレクトリの ACL (アクセス制御リスト) を継承します。
- このアプリケーションは、認証情報を暗号化したり、システムキーチェーンに保存したりしません。同じユーザーとして実行されている悪意のあるネイティブプログラムでも、これらの情報を読み取ることが可能です。

これらのディレクトリを、ワークスペース、共有フォルダ、バージョン管理システム、または公開バックアップには配置しないでください。サインインプラグインを使用しなくても、直接APIキー接続は引き続き機能します。

## ブラウザとペアリングする

プラグインをインストールおよび有効化した後、同じコンピューターで次のコマンドを実行してください:

```sh
i plugins serve chatgpt --origin https://i.lninl.com --port 0
```

Claude の場合は、上記のコマンドの `chatgpt` を `claude` に置き換えます。 ターミナルを起動したまま、印刷されたペアリングリンクを開いてください。ページ上でプラグイン、アカウント、モデルを確認し、保存します。ペアリングは、まず未保存のドラフトを作成し、既存の接続を自動的に置き換えることはありません。サービスを再起動した後、新しいリンクを使用してください。ペアリングリンクを共有しないでください。それぞれには、ローカルの機能秘密が含まれています。

このサービスは `127.0.0.1` のみで動作し、指定されたページオリジンにのみ関連付けられ、任意のURLをプロキシしません。ローカルネットワークへのアクセスが必要なHTTPSページの場合、ローカルネットワークへのアクセス許可が必要となる場合があります。ペアリングはブラウザの権限やCORSを回避しません。スマートフォンはネイティブプラグインを単独で実行できません。また、ブラウザとの接続を切断しても、ネイティブアカウントからのログアウトはされません。

## ChatGPT の制限とトラブルシューティング

このプラグインは、公式のOAuth動的クライアント登録、PKCE、独自のホストID、および独自の認証情報の保存を使用します。あなたの個人的な `~/.codex/auth.json` ファイルを読み取ったり、独自のクライアントIDを借りたりすることはありません。公式のサインインに関するドキュメント [https://developers.openai.com/siwc/token-sharing-open-source/sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) および、プロファイルとセッションに関するドキュメント [https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) を参照してください。

Inferenceは、`backend-api`ではなく、公開されているResponses APIを使用します。OpenAIは、利用資格、ワークスペースポリシー、および認証制限を決定します。サインインは、Inferenceへのアクセスを保証するものではありません。サブスクリプションベースの認証では、`store: false`と`stream: true`という固定設定を使用します。現在のプレビューでは、最大出力トークン設定は無視されます。詳細については、[プレビューの制限](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)を参照してください。

認証コードの交換、セッションの更新、およびネットワークエラーに関連する失敗を特定します。診断では、生のトークンエンドポイントの応答、資格情報、または認証コードを表示せずに、HTTPステータスコードのみが表示されます。認証またはモデルの要求が失敗した場合、自動的に再試行されません。コードの交換が拒否された場合は、再度サインインし、バージョン、システム時計、ネットワーク、およびプロキシ設定を確認してください。ステータスコードだけでは、なぜ拒否されたのかを特定できません。

## Claude Console の制限

[公式のインストールガイド](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/quickstart) に従って、`ant` をインストールし、PATH に設定されていることを確認してください。接続パッケージは `ant` を同梱したり、インストールスクリプトを実行したりしません。その後、`i login claude` を使用してください。

このプラグインは、隔離された HOME、`ANTHROPIC_CONFIG_DIR`、および独自のプロファイルを使用します。既存の Claude Code や個人の ant プロファイルは読み込まれません。現在は、1 つの Console プロファイルのみをサポートしています。再認証により、ワークスペースを変更できます。その後のリクエストでは、新しいワークスペースを使用できる場合があります。必要に応じて、新しいセッションを開始してください。**Claude は Console API の利用料金で請求され、Pro / Max の利用枠は使いません。**

## 検証範囲

自動テストは、隔離されたディレクトリとローカルのOAuth/TLS設定を使用します。実際の個人用トークンを使用したり、あなたの代理としてアクセスを許可したり、課金用のリクエストを送信したりしません。オフラインでテストをパスすることは、プロバイダーが実際の口座へのアクセスを許可するかどうかを証明するものではありません。ヘルパーは、内部のワーカーおよびサービスプロトコルを保持し、ユーザーインターフェースを通じて `i` を使用します。
