# จัดการปลั๊กอินเข้าสู่ระบบด้วย i

> **Claude คิดค่าบริการผ่าน Console API ไม่ได้ใช้โควตาของแพ็กเกจ Pro หรือ Max**
> การเข้าสู่ระบบโดยไม่กรอกคีย์ API ไม่ได้ทำให้ส่งคำขอได้ฟรี โปรดตรวจสอบองค์กร พื้นที่ทำงาน และสิทธิ์การเรียกเก็บเงินใน Console ก่อนอนุญาตให้เข้าถึง

ใช้ `i` เพื่อจัดการการเชื่อมต่อ โดยไม่ต้องจำชื่อไฟล์ executable หรือเขียนการตั้งค่าการเชื่อมต่อด้วยตนเอง Plugin สำหรับการเข้าสู่ระบบแบบ native จะทำงานโดยใช้สิทธิ์ของผู้ใช้ระบบปฏิบัติการของคุณ ไม่ใช่ plugin สำหรับเครื่องมือ WASM ใน workspace โปรดใช้ package การติดตั้งที่ถูกต้อง

## ตั้งค่าจากเทอร์มินัล

เริ่มต้นด้วยคำสั่ง `i` และป้อนคำสั่งการจัดการในระดับท้องถิ่น แม้ว่าคุณยังไม่ได้กำหนดค่าแบบจำลอง:

```text
/plugins
```

เลือกใช้ ChatGPT หรือ Claude, ตรวจสอบสิทธิ์การใช้งาน, จากนั้นติดตั้งและเปิดใช้งานปลั๊กอิน จากนั้นพิมพ์ `/login` เลือกปลั๊กอินสำหรับการเข้าสู่ระบบ และยืนยันในเบราว์เซอร์ของระบบของคุณ เลือกโมเดลจากรายการ หรือป้อน ID ของโมเดลที่คุณต้องการใช้ เมื่อดำเนินการสำเร็จ `i` จะบันทึกการเชื่อมต่อสำหรับการทำงานครั้งต่อไป คุณยังสามารถป้อนคำสั่งได้โดยตรง:

```text
/plugins install chatgpt
/plugins enable chatgpt
/login chatgpt
```

ใช้ `/cancel` เพื่อปิดเมนู คุณไม่สามารถแก้ไขปลั๊กอินหรือการเชื่อมต่อขณะที่งานกำลังทำงานอยู่ การขออนุมัติและการแสดงรายการโมเดลจะไม่ส่งคำขอการสร้าง การเปลี่ยนแปลงการเชื่อมต่อจะเกิดขึ้นหลังจากที่ทั้งการเข้าสู่ระบบและการเลือกโมเดลสำเร็จ การล้มเหลวและการยกเลิกจะยังคงการเชื่อมต่อเดิมไว้ และ `i` จะบันทึกสำเนาการตั้งค่าส่วนตัวก่อนทำการสลับ

## จัดการปลั๊กอินผ่านบรรทัดคำสั่ง

### เปลี่ยนโมเดลและระดับการให้เหตุผล

`/model` อ่านแค็ตตาล็อกโมเดลจากปลั๊กอินการเชื่อมต่อแบบท้องถิ่นปัจจุบัน เลือกหมายเลขจากรายการ หรือป้อน ID ของโมเดลโดยตรง การเชื่อมต่อ API-key มาตรฐานจะไม่ทำการค้นหาแค็ตตาล็อก ให้ป้อน ID ของโมเดลด้วยตนเอง: การดำเนินการนี้จะไม่ต้องเข้าสู่ระบบหรือสลับบัญชี

```text
/model
/model status
/model gpt-6.1-sol
/model gpt-6.1-sol high
/model effort high
/model effort auto
```

เปลี่ยนการตั้งค่าเฉพาะเมื่อไม่มีงาน, การอนุมัติ หรือรายการที่ค้างอยู่ การตั้งค่าจะถูกบันทึกสำหรับแต่ละการเชื่อมต่อ พร้อมกับการสำรองข้อมูลส่วนตัวก่อนการบันทึก เมื่อยกเลิกรายการแบบจำลอง การตั้งค่าจะยังคงเดิม การสลับเฉพาะแบบจำลองจะรีเซ็ตความพยายามกลับไปเป็นค่าเริ่มต้นของผู้ให้บริการ เพื่อให้คุณไม่จำเป็นต้องถ่ายโอนการตั้งค่าของแบบจำลองอื่น `auto` และ `default` จะไม่ระบุความพยายาม ค่าอื่นๆ ได้แก่ `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, และ `max` ไม่ใช่ทุกแบบจำลองที่รองรับค่าเหล่านี้ และแค็ตตาล็อกอาจไม่ได้โฆษณาความสามารถของมัน การเปลี่ยนการตั้งค่านี้ไม่ส่งคำขอสร้างผลลัพธ์ที่คิดค่าบริการ ผู้ให้บริการจะตรวจสอบการสนับสนุนในคำขอถัดไป Responses API ใช้ `reasoning.effort` ส่วน Chat Completions API ใช้ `reasoning_effort` Claude ใช้ `output_config.effort` พร้อมกับการคิดเชิงปรับตัว `none` จะขอให้ปิดการคิดบนแบบจำลองที่รองรับโหมดนี้ ไม่ควรสมมติว่าแบบจำลองทุกแบบรองรับความพยายามที่สูงขึ้นหรือการปิดการคิด ศึกษา [OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning) และ [Claude effort](https://platform.claude.com/docs/en/build-with-claude/effort)

```sh
i plugins list
i plugins install chatgpt
i plugins enable chatgpt
i login chatgpt
i plugins status chatgpt
i plugins models chatgpt
i plugins logout chatgpt
i plugins disable chatgpt
i plugins update chatgpt
i plugins reconnect chatgpt
i plugins remove chatgpt
```

เปลี่ยนไปใช้บัญชีที่มีอยู่ โดยใช้คำสั่ง `i plugins use chatgpt ACCOUNT_ID` ใช้คำสั่ง `i login chatgpt --account ACCOUNT_ID` เพื่อยืนยันการลงทะเบียนที่มีอยู่ หรือใช้คำสั่ง `i plugins logout chatgpt --account ACCOUNT_ID` เพื่อออกจากระบบบัญชีเฉพาะ การยืนยันใหม่จะทำการลงทะเบียนโดยไม่ต้องคัดลอกโทเค็นเก่า และจะไม่เปลี่ยนแปลงบัญชีในปัจจุบันจนกว่าคุณจะยืนยันโมเดล

หากต้องการจัดการปลั๊กอิน Claude Console ให้ใช้ `claude` แทน `chatgpt` การติดตั้งและการอัปเดตจำเป็นต้องยืนยัน หลังจากอัปเดตแล้ว ให้เปิดใช้งานปลั๊กอินอีกครั้งและเข้าสู่ระบบเพื่อหลีกเลี่ยงการแทนที่การเชื่อมต่อที่ใช้งานอยู่โดยอัตโนมัติ หากคุณอัปเดตเฉพาะส่วนเสริมและต้องการใช้บัญชีเดิม ให้เปิดใช้งานปลั๊กอินและรันคำสั่ง `i plugins reconnect chatgpt` ซึ่งจะรักษาบัญชีและค่าตั้งค่าแบบเดิมไว้ และเชื่อมต่อการเชื่อมต่อที่ใช้งานอยู่กับตัวโปรแกรมใหม่ที่ได้รับการยืนยัน ไม่จำเป็นต้องเข้าสู่ระบบหรือส่งคำขอสร้างใหม่ ในระหว่างการติดตั้ง `i` จะแสดงการตรวจสอบเวอร์ชัน, ขนาดไฟล์ที่ดาวน์โหลด, การตรวจสอบ checksum และบันทึกความคืบหน้า ใช้ `/cancel` เพื่อหยุดการทำงาน การเชื่อมต่อจะหมดเวลาหลังจาก 10 วินาที และการดาวน์โหลดแต่ละครั้งอาจใช้เวลาสูงสุด 120 วินาที ความล้มเหลวจะไม่ทำให้ระบบพยายามใหม่โดยอัตโนมัติหรือเปิดใช้งานปลั๊กอิน GitHub ใช้ตัวแปรสภาพแวดล้อมของพร็อกซีในเทอร์มินัล ไม่ใช่การตั้งค่าพร็อกซีของเบราว์เซอร์ หากจำเป็น ให้เริ่มต้นด้วย `HTTPS_PROXY=http://127.0.0.1:3067 i` โดยแทนที่ที่อยู่และพอร์ตด้วยการตั้งค่าพร็อกซีของคุณ

นอกจากนี้ คุณยังสามารถเปลี่ยนกฎการใช้งานพร็อกซีได้จากภายใน `i` โดยค่าเริ่มต้น กฎจะถูกบันทึกสำหรับผู้ใช้แต่ละคนในไฟล์ `~/.i/config/proxy.json` (ภายใต้ `I_CONFIG_DIR` หากมีการตั้งค่า) ไม่ใช่ในพื้นที่ทำงาน

```text
/proxy
/proxy 3067
/proxy :3067
/proxy 127.0.0.1:3067
/proxy socks5://127.0.0.1:3067
/proxy no
/proxy env
/proxy chatgpt 3067
/proxy claude no
/proxy plugins no
/proxy model 3067
/proxy chatgpt default
```

ระบบใช้กฎตามลำดับดังนี้: กฎเฉพาะการใช้งาน ค่าเริ่มต้นของผู้ใช้ แล้วจึงใช้ค่าจากสภาพแวดล้อมหรือการตั้งค่าเดิม หากระบุ `no` อย่างชัดเจน ระบบจะไม่กลับไปใช้พร็อกซีจากตัวแปรสภาพแวดล้อม การเปลี่ยนแปลงมีผลเฉพาะกับการทำงานครั้งถัดไป โดยจะไม่ขัดจังหวะหรือส่งคำขอที่กำลังทำงานซ้ำ ให้ตั้งค่าเบราว์เซอร์และบริการแยกที่กำลังทำงานอยู่ต่างหาก รองรับ HTTP, HTTPS, SOCKS5 และ SOCKS5h การเรียกกลับเพื่ออนุญาตบนเครื่องจะไม่ผ่านพร็อกซี URL ของพร็อกซีต้องไม่มีชื่อผู้ใช้ รหัสผ่าน พารามิเตอร์คำค้น หรือพาธ เพื่อไม่ให้ข้อมูลรับรองไปปรากฏในประวัติคำสั่ง คำสั่งนี้เป็นคำสั่งในตัวของโฮสต์และไม่เปิดเผยการตั้งค่าพร็อกซีหรือข้อมูลรับรองบัญชีให้ปลั๊กอิน WASM ในพื้นที่ทำงาน การนำปลั๊กอินออกจากรายการติดตั้งจะเก็บแพ็กเกจเดิมและข้อมูลรับรองไว้ และไม่เพิกถอนสิทธิ์ที่ผู้ให้บริการ หากต้องการออกจากระบบ ให้เรียก `i plugins logout NAME` ก่อนปิดใช้งานหรือนำปลั๊กอินออก หากยังไม่ได้รับการยืนยันว่ามีการเพิกถอนสิทธิ์ ให้ตรวจสอบในการตั้งค่าบัญชีของผู้ให้บริการ

โปรแกรมติดตั้งจะดาวน์โหลดไฟล์เชื่อมต่อที่เหมาะสมจาก GitHub Release อย่างเป็นทางการ จากนั้นจะตรวจสอบ SHA-256 ที่ GitHub ให้มา, รายการไฟล์ ZIP ที่ได้รับอนุญาต, และแพลตฟอร์มเป้าหมาย จากนั้นจะตรวจสอบความถูกต้องของไฟล์ที่สามารถรันได้ก่อนการใช้งานแต่ละครั้ง หากไม่มีแพลตฟอร์มที่ตรงกัน โปรแกรมจะไม่รันสคริปต์การติดตั้งจากบุคคลที่สาม หากไม่มีแพลตฟอร์มที่ตรงกัน โปรแกรมจะหยุดทำงานแทนที่จะรันสคริปต์การติดตั้งจากบุคคลที่สาม การตรวจสอบ checksum เป็นการตรวจสอบความสมบูรณ์ ไม่ใช่การตรวจสอบตัวตนของผู้เผยแพร่ ไฟล์ macOS **connection packages** ไม่ได้รับการลงนามหรือตรวจสอบโดย Developer ID การติดตั้งปลั๊กอินจะไม่เปลี่ยนแปลง PATH หรือต้องการสิทธิ์ของผู้ดูแลระบบ

นักพัฒนาสามารถทดสอบแพ็กเกจที่สร้างขึ้นในเครื่องด้วยคำสั่ง `i plugins install chatgpt --package /absolute/path/package.zip` หลังจากยืนยันแล้ว ตัวติดตั้งยังคงตรวจสอบสมาชิกของไฟล์และแพลตฟอร์มเป้าหมาย ปลั๊กอินจะเริ่มต้นในสถานะปิด และตรวจสอบข้อมูลที่สามารถรันได้ก่อนใช้งาน แพ็กเกจที่สร้างขึ้นในเครื่องจะถูกระบุว่าเป็น `local-build` และยังไม่ได้ยืนยันว่าเป็นเวอร์ชันอย่างเป็นทางการ ติดตั้งเฉพาะโค้ดที่มาจากแหล่งที่คุณเชื่อถือ การยืนยันจากเบราว์เซอร์ไม่ได้หมายความว่าการเข้าสู่ระบบเสร็จสมบูรณ์ รอให้เทอร์มินัลดำเนินการแลกเปลี่ยนโทเค็น, การตรวจสอบตัวตน และการเลือกโมเดลให้เสร็จสิ้น

ไฟล์ `desktop.json` ระดับผู้ใช้รุ่นเก่า อาจยังคงระบุคำว่า `search` และ `find_files` ซึ่งปัจจุบันได้ถูกรวมเข้ากับส่วนหลักแล้ว เมื่อโหลด ระบบจะลบรายการค้นหาแบบเก่าที่รู้จัก และผูกเชื่อมต่อกับตัวทำงานแบบเก่าที่อยู่ในไดเรกทอรีการกำหนดค่าของผู้ใช้เดียวกันกับโปรแกรมที่กำลังรันอยู่ โดยไม่เปลี่ยนแปลงไฟล์บนดิสก์ ชื่อที่ขัดแย้งสำหรับตัวทำงานและปลั๊กอินที่กำหนดเองยังคงทำให้เกิดข้อผิดพลาด ระบบจะไม่ทำการตรวจสอบซ้ำซ้อน ข้อผิดพลาดเหล่านี้เกิดขึ้นก่อนการร้องขอแบบจำลอง ดังนั้นจึงไม่จำเป็นต้องเข้าสู่ระบบอีกครั้ง

### วินิจฉัยข้อผิดพลาดในการสร้างผลลัพธ์

การเชื่อมต่อ ChatGPT แบบพื้นฐานใช้ API Responses โดยมี `store:false` และ `stream:true` ไม่ใช่ Chat Completions เทอร์มินัลให้ความสำคัญกับ SSE แต่ก็สามารถรับ `application/json` Responses ได้ หากมี `object:response`, ID ที่ถูกต้อง, `status:completed`, และผลลัพธ์ที่ถูกต้อง หากไม่มี header `Content-Type` จะตรวจจับ SSE หรือ JSON จากเนื้อหา และทำการตรวจสอบในลักษณะเดียวกัน จะปฏิเสธ HTML หรือประเภทสื่ออื่นๆ ที่ระบุไว้โดยชัดเจน หากไม่สามารถใช้งานได้ การวินิจฉัยข้อผิดพลาดจะแสดงเฉพาะหมวดหมู่รูปแบบและจำนวนไบต์ ไม่ใช่เนื้อหาการตอบกลับ HTML, Chat Completions objects, JSON ที่ไม่ถูกต้อง และการเรียกใช้เครื่องมือที่ไม่สมบูรณ์จะไม่ได้รับการยอมรับ การเปลี่ยนแปลงรูปแบบการตอบกลับจะไม่ทำให้ต้องส่งคำขอซ้ำ การทำงานของเว็บเซิร์ฟเวอร์ในเครื่องจะส่ง SSE ที่ถูกต้อง หากเนื้อหาหรือการตอบกลับเป็น JSON จะทำการตรวจสอบการตอบกลับทั้งหมดก่อนที่จะส่ง SSE ที่ถูกต้องไปยังเบราว์เซอร์ เส้นทางการทำงานนี้รอการตอบกลับและไม่ส่งซ้ำโดยอัตโนมัติ ข้อผิดพลาด HTTP 400 ในเบราว์เซอร์ ไม่ได้หมายความว่าสถานะ upstream จะผิดพลาด การวินิจฉัยจะแยกแยะข้อผิดพลาด HTTP, ความล้มเหลวของเครือข่าย และข้อผิดพลาดของรูปแบบ

หากเกิดข้อผิดพลาด ระบบวินิจฉัยจะระบุขั้นตอนที่เกิดปัญหา: การเตรียมคำขอ, การอนุมัติ, HTTP, รูปแบบการตอบกลับ, หรือการวิเคราะห์ข้อมูลแบบต่อเนื่อง HTTP diagnostics จะแสดงเฉพาะสถานะ, รหัสข้อผิดพลาดที่ทราบ, หรือชื่อพารามิเตอร์ และ ID คำขอที่จำกัดเท่านั้น ไม่มีการแสดงข้อผิดพลาด, คำแนะนำ, หรือโทเค็นโดยตรง ข้อผิดพลาดของเครือข่ายหรือรูปแบบจะไม่ทำให้คุณออกจากระบบหรือเปลี่ยนบัญชี, รุ่น, หรือเส้นทางการเรียกเก็บเงิน API โดยอัตโนมัติ

## การตั้งค่าและข้อมูลรับรอง

- ไฟล์ `<config_dir>/native-plugins.json` เก็บข้อมูลเกี่ยวกับตำแหน่งการติดตั้ง, ค่า hash, และสถานะการเปิดใช้งาน, ไม่ใช่โทเคน OAuth
- `<data_dir>/connections/accounts/NAME` เป็นที่เก็บข้อมูลประจำตัวของปลั๊กอิน; ปลั๊กอิน WASM ไม่ได้รับข้อมูลเหล่านี้
- เมนูสำหรับการลงชื่อเข้าใช้จะทำการกำหนดค่าแบบจำลองให้เสร็จ คุณไม่จำเป็นต้องเขียนไฟล์ `chatgpt.json`
- macOS และ Linux ใช้ไดเรกทอรีและสิทธิ์การเข้าถึงไฟล์ส่วนตัว ในขณะที่ Windows จะสืบทอดสิทธิ์การเข้าถึงไดเรกทอรีของผู้ใช้
- แอปพลิเคชันนี้ไม่ได้เข้ารหัสข้อมูลประจำตัว หรือเก็บไว้ในระบบกุญแจ ดังนั้น โปรแกรมพื้นฐานที่เป็นอันตรายที่ทำงานภายใต้ผู้ใช้เดียวกันก็ยังสามารถอ่านข้อมูลเหล่านั้นได้

โปรดอย่าเก็บไดเรกทอรีเหล่านี้ไว้ในพื้นที่ทำงาน, โฟลเดอร์ที่ใช้ร่วมกัน, ระบบควบคุมเวอร์ชัน หรือสำเนาสำรองสาธารณะ การเชื่อมต่อ API-key ยังคงทำงานได้โดยไม่ต้องใช้ปลั๊กอินสำหรับเข้าสู่ระบบ

## จับคู่กับเบราว์เซอร์

หลังจากติดตั้งและเปิดใช้งานปลั๊กอินแล้ว ให้รันคำสั่งนี้บนคอมพิวเตอร์เครื่องเดียวกันกับที่ใช้เบราว์เซอร์:

```sh
i plugins serve chatgpt --origin https://i.lninl.com --port 0
```

หากใช้ Claude ให้เปลี่ยน `chatgpt` ในคำสั่งด้านบนเป็น `claude` เปิดเทอร์มินัลทิ้งไว้ และเปิดลิงก์เชื่อมต่อที่พิมพ์ออกมา ยืนยันปลั๊กอิน, บัญชี และโมเดลบนหน้าเว็บ จากนั้นบันทึก การเชื่อมต่อจะสร้างร่างที่ไม่บันทึกไว้ก่อน และไม่ทำการแทนที่การเชื่อมต่อที่มีอยู่โดยอัตโนมัติ ใช้ลิงก์ใหม่หลังจากรีสตาร์ทบริการ ห้ามแชร์ลิงก์เชื่อมต่อ: แต่ละลิงก์มีความลับเฉพาะ

บริการนี้ทำงานเฉพาะกับ `127.0.0.1` เท่านั้น, เชื่อมต่อกับที่อยู่ของหน้าเว็บที่ระบุ, และไม่สามารถใช้เพื่อเข้าถึง URL ใดๆ ได้ HTTPS ที่เข้าถึง loopback อาจต้องมีการอนุญาตจากเครือข่ายภายใน A การจับคู่จะไม่ข้ามการอนุญาตของเบราว์เซอร์หรือ CORS ได้ โทรศัพท์ไม่สามารถรัน plugin ได้ด้วยตัวเอง, และการลบการเชื่อมต่อกับเบราว์เซอร์จะไม่ทำให้บัญชี native ถูกปิด

## ข้อจำกัดของ ChatGPT และการแก้ปัญหา

ปลั๊กอินนี้ใช้การลงทะเบียนผู้ใช้แบบไดนามิกโดยใช้ OAuth อย่างเป็นทางการ, PKCE, ตัวระบุเฉพาะสำหรับโฮสต์, และการจัดเก็บข้อมูลที่แยกต่างหาก โดยไม่อ่านไฟล์ `~/.codex/auth.json` ส่วนตัวของคุณ หรือใช้ตัวระบุผู้ใช้ที่เป็นกรรมสิทธิ์ ปรึกษาเอกสารการลงทะเบียนอย่างเป็นทางการที่ [ลิงก์](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) และข้อมูลเกี่ยวกับโปรไฟล์และเซสชันที่ [ลิงก์](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)

Inference ใช้ API สาธารณะ Responses API ไม่ใช่ `backend-api` ส่วน OpenAI กำหนดเกณฑ์การเข้าถึง นโยบายพื้นที่ทำงาน และขีดจำกัดการอนุญาต การเข้าสู่ระบบไม่รับประกันการเข้าถึง Inference การอนุญาตแบบสมัครสมาชิกใช้การตั้งค่าคงที่คือ `store: false` และ `stream: true` ปัจจุบัน การทดลองใช้ยังไม่คำนึงถึงการตั้งค่าจำนวนโทเค็นสูงสุด โปรดดู [ข้อจำกัดของการทดลองใช้](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

ความผิดพลาดจะเกิดขึ้นจากการแลกเปลี่ยนรหัส, การรีเฟรชเซสชัน, และข้อผิดพลาดของเครือข่าย การวินิจฉัยจะแสดงรหัสสถานะ HTTP โดยไม่แสดงผลตอบกลับจากปลายทางของโทเค็น, ข้อมูลประจำตัว, หรือรหัสการยืนยัน หากการยืนยันหรือคำขอแบบจำลองล้มเหลว จะไม่ถูกส่งซ้ำโดยอัตโนมัติ หากการแลกเปลี่ยนรหัสถูกปฏิเสธ ให้ลองเข้าสู่ระบบอีกครั้ง และตรวจสอบเวอร์ชัน, นาฬิกาของระบบ, เครือข่าย, และการตั้งค่าพร็อกซี รหัสสถานะเพียงอย่างเดียว ไม่สามารถบอกได้ว่าทำไมจึงถูกปฏิเสธ

## ข้อจำกัดของ Claude Console

ทำตามคู่มือการติดตั้ง [อย่างเป็นทางการ](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/quickstart) เพื่อติดตั้ง `ant` และตรวจสอบให้แน่ใจว่าอยู่ใน PATH ด้วย แพ็กเกจการเชื่อมต่อจะไม่รวม `ant` หรือรันสคริปต์การติดตั้งให้คุณ จากนั้นใช้คำสั่ง `i login claude`

ปลั๊กอินนี้ใช้ HOME ที่แยกต่างหาก (`ANTHROPIC_CONFIG_DIR`) และโปรไฟล์ของตนเอง โดยไม่อ่านโค้ด Claude Code หรือโปรไฟล์ของผู้ใช้ที่มีอยู่ นอกจากนี้ ปัจจุบันรองรับโปรไฟล์ Console เพียง 1 โปรไฟล์ การยืนยันใหม่สามารถเปลี่ยนพื้นที่ทำงาน และคำขอในภายหลังอาจใช้พื้นที่ทำงานใหม่ได้ หากจำเป็น ให้เริ่มต้นเซสชันใหม่ **Claude คิดค่าบริการผ่าน Console API ไม่ได้ใช้โควตาของแพ็กเกจ Pro หรือ Max**

## ขอบเขตการตรวจสอบ

การทดสอบอัตโนมัติใช้ไดเรกทอรีที่แยกต่างหากและไฟล์ตั้งค่า OAuth/TLS ในเครื่องเท่านั้น ไม่มีการใช้โทเค็นส่วนตัวจริง, การอนุญาตให้เข้าถึงแทนคุณ, หรือการส่งคำขอที่ต้องชำระเงิน การทดสอบที่ทำงานแบบออฟไลน์ไม่ได้พิสูจน์ว่าผู้ให้บริการจะอนุญาตให้เข้าถึงบัญชีจริงได้ ตัวช่วย (Helpers) ยังคงรักษาโปรโตคอลภายในของตนเอง และการทำงานที่ผู้ใช้เห็น จะผ่าน `i`
