# 浏览器工作区：终端式 UI、独立会话与刷新恢复

状态：讨论方向已获用户确认；本文待用户审阅，尚未进入本轮实施计划。以用户修改后的当前工作区代码为基线，不覆盖其未提交变更。

## 1. 目标与取舍

用户需要保留紧凑终端体验，但不需要理解 Harness 的内部参数才能使用。文件隔离、独立对话与模型连接必须清楚区分；刷新后恢复文件、当前 Session、打开的会话和阅读/输入状态，并补齐回归测试。

本文替代 `2026-10-22-workspace-session-tabs-design.md` 中会话仅存内存、关闭 Tab 丢失会话及旧设置布局的约定。此前已实现的 WASM、SSE、OPFS、ZIP、direct/relay 和 PWA 保留，不重写 Native provider。

采用「工作区选择 + 单层会话 Tabs + 折叠文件区 + 分组设置」。不采用工作区/目录/会话三层混排，也不直接给当前单 Agent 增加伪标签。相比仅修改 CSS，本方案还修正状态归属与持久化；相比完整 IDE，不引入编辑器、终端进程或后端执行环境。

三个独立可验收阶段：
1. 本轮：安全与回归修复、真实 Workspace/Session、刷新恢复、终端式 UI 和设置。
2. 后续独立计划：临时工作区和 /tmp 的文件系统挂载；本轮不显示尚无实现的操作按钮。
3. 后续预览方案：完成隔离可行性验证再定架构，不将未验证的 Service Worker iframe 方案混入本轮交付。

## 2. 已验证的问题与先决修复

审查基线存在：模型/目录/会话字符串 innerHTML 注入、单 Agent 串工作区历史、旧配置缺 custom_headers 导致初始化中断、清配置后 profiles 密钥复活、PWA 控件移除使注册异常、i18n.js 未进发布清单、Cancel 消失、refresh 不渲染文件、自定义 Header 仅测试链路生效、Native 会话绝对/相对路径回归及 FileSystem 测试实现缺方法。

这些问题先写可复现回归测试，观察失败，再修正。不能仅更改断言或替换测试路径掩盖真实 CLI 回归，也不能因旧单测通过便声称端到端正常。

不可信内容默认 textContent。代码高亮仅处理受控 code 节点，不把模型正文拼成 HTML；依赖本地打包、进入发布清单，不能让 CDN 脚本获得保存 key 的 origin 权限。暂不依赖 Markdown 渲染；如实现 Markdown，必须单独验证输出清理与安全链接策略。

## 3. 信息架构与界面

```text
[工作区 A ▾] [会话 1] [会话 2] [+]                         [设置]
----------------------------------------------------------------
[文件 ▸]       当前会话标题                     [预览*] [下载 ▾]
               对话 / 工具事件 / 当前任务审批

               [输入任务或粘贴文件……                  ] [发送/停止]
----------------------------------------------------------------
已保存 / 保存中 / 保存失败 · 当前模型 · 任务状态
```

预览星号为后续能力，未实现前不显示假可用按钮。

- Workspace 是持久文件隔离边界；Session 是历史、终端、草稿和任务边界；Tab 是打开 Session 的视图。
- 同工作区多会话共享文件但不共享模型历史；不同工作区文件互相隔离。
- 工作区选择器列出工作区；会话 Tabs 仅展示当前工作区打开的会话；其他工作区的打开状态仍保存。
- + 默认在当前工作区创建新会话；工作区菜单另有新建工作区。文案明确前者共享文件、后者隔离文件。
- 关闭 Tab 只关闭视图，不删除持久会话；从会话历史列表可重新打开，不再要求用户记 /resume 命令。默认始终保留一个可用会话。
- 文件区默认折叠，展示真实文件/目录，提供上传、选择 ZIP 范围和入口；不得把会话目录树当成实际工作区文件。
- 清空显示、重置对话、重命名和关闭放入当前会话菜单，不与工作区操作混淆。清空显示不删模型历史，重置对话先确认且不删文件；新建对话不破坏旧会话。
- 下载默认导出当前工作区，可选择具体文件/目录；下载记录归发起 Session，不以 filename 作为跨会话唯一身份。
- 显式发送按钮空闲时为发送，活动时为停止。切到其他会话可阅读和编辑草稿，但不误取消后台会话；显示跳转运行会话入口。
- 消息区区分用户、模型、工具、系统和错误；正文使用中性色，强调色用于状态，不再把整段回复涂橙色。工具详情和长输出可折叠，复制只复制对应消息。

手机单列，Tabs 横向滚动，文件区与设置采用覆盖面板；输入使用至少 16px 字号，控件至少 40px 高，适配动态视口和安全区。无横向整页溢出。aria-selected、可访问按钮名、键盘焦点与屏幕阅读器状态真实反映活动会话。

## 4. 设置与连接配置

设置分为模型连接、工作区与恢复、外观、高级四组。桌面使用有分组导航的面板，手机单列；打开时聚焦面板、Esc 关闭并返回触发按钮，避免背景误操作。

模型连接默认仅显示连接配置选择、API 地址、模型、API Key（显示/隐藏）、测试连接和保存修改。模型连接可多配置，内部用稳定 ID；显示名不承担存储主键或路径作用。操作为添加连接、保存修改、删除此连接，不再混用 Load/Save as/Save。

direct 默认；仅 relay 时显示独立访问 token 和密钥经过自有服务的提示。Stream 默认开启；自定义 Headers、token 上限/字段名、步数等归高级。自定义 Headers 必须是字符串键值 JSON 对象，非法输入明确报错；禁止覆盖认证、relay token、Host/Cookie/Origin 等保留头，不能静默忽略。真正请求与测试按钮共用 endpoint 规范化和受限传输实现。

测试连接是用户明确发起的、可能计费的小请求，点击前文案说明；使用选定 token 参数、POST JSON、统一 48 MiB/180 秒上限、取消与真实状态，不绕过错误处理。错误先对完整有界内容脱敏，再截断。恢复页面不自动测试或调用模型。

配置的编辑态、已应用态和持久态分开。状态只在真正成功后显示未保存修改/已应用（仅本次）/已保存在此设备；保存失败不能被后续 configure 成功覆盖。开启记忆才保存凭据，关闭记忆删除所有持久凭据而保留本页内存值；配置名称/非敏感参数可保留，但刷新后必须要求重新输入 key。

清除所有凭据放进危险操作区并二次确认，覆盖旧 CONFIG_KEY 与 profiles 中所有凭据及活动配置，不删除文件/会话；删除此连接提示关联会话将需要重新选择连接，不偷偷删除历史。明确提示同源脚本可读取已保存 key，不在共享设备记忆。

旧 version=1/2 缺 custom_headers 时补空字符串；旧 profiles 逐条验证、迁移后保留有效配置。损坏配置隔离并提示，不阻止打开文件/会话，不打印敏感原文。升级不能自动更改网络接收方。

## 5. 存储与刷新恢复

文件继续 OPFS；Workspace/Session 元数据、消息快照和 UI 状态使用 IndexedDB 事务；连接配置沿用明确记忆语义，不复制进 Session 快照。

数据关系：Workspace(id,name,storageKind)；Session(id,workspaceId,name,connectionId,history,transcript,draft,status,revision)；UiState(activeWorkspaceId,activeSessionId,openedSessionIds,sidebar/settings preferences,scroll positions)。具体持久 schema 与升级版本由实施计划固定，禁止直接保存 innerHTML/DOM 节点或 JS 回调。

旧 OPFS workspace/ 始终映射稳定 ID=default 的默认工作区，不搬迁、不删除原文件。新工作区位于 harness/workspaces/<UUID>/。名称最多 80 字符，去空白且非空，显示名不用于路径。管理记录不在模型可见目录或默认 ZIP 中。

目录与数据库不能跨系统原子提交：先创建独立目录，再提交工作区记录；失败不报成功。启动可扫描 Harness 管理目录的合法 UUID 孤立目录，提示恢复，不枚举或删除无关 OPFS 数据。文件系统始终以选定根验证路径。

每个 Session 拥有独立 BrowserAgent，创建时固定 Workspace 根；提供验证后的历史导入/导出与 checkpoint 回调，不能仅持久化界面字符串。会话保存连接标识但不保存 key；恢复后连接缺失或模型/endpoint 不匹配时提示选择或新建会话，不把历史自动发送给另一提供商。

恢复顺序：初始化存储/迁移 → 恢复工作区与会话记录 → 验证模型历史 → 创建绑定根的 Agent → 渲染打开的 Tabs、活动会话、输出、草稿和 UI → 按用户记忆设置加载配置。文件列表按真实 OPFS 刷新，不以旧快照冒充当前文件。

状态在正常交互中持续保存：完整模型/工具 checkpoint 必须等待持久化完成；草稿、滚动位置与流式展示快照可短时合并写入。显式刷新/正常重开恢复最后成功提交的快照，不依赖 beforeunload 才保存。显示保存中/已保存/保存失败；配额不足或存储拒绝不能静默清状态或假装保存成功。流过程中系统突然终止可能丢失最后尚未提交的展示片段，必须如实说明。

Session 自动保存是用户此次明确要求的行为，与 Remember API key 分离。会话可能包含用户敏感文本，设置中说明本机保存并提供单独的清除会话记录入口；该操作不与清除凭据混为一谈。浏览器回收或清站点数据仍会删本地数据，ZIP 仅备份文件，不声称备份会话。

## 6. 中断、工具与并发

首期应用窗口同一时间只运行一个任务；工作区上传/导出与任务互斥。跨浏览器窗口通过工作区 Web Lock 和会话 revision 检查避免并发覆盖；不支持锁时明确拒绝受保护写入，不使用无竞争保证的 localStorage 标志伪造锁。其他窗口变更不无提示覆盖当前草稿。

所有回调绑定 workspaceId/sessionId/requestId；切换视图不改变请求归属。审批只可在发起 Session 操作；后台会话显示等待标识。活动 Session 禁止清空流输出或重置，设置凭据和连接修改在任务期间禁止。

刷新后进行中的任务标记已中断，保留已提交的文字，不自动发起 HTTP、不重复工具、不恢复旧审批授权。已完成文件副作用不回滚。

工具执行前持久化调用身份及开始状态，执行完成后持久化真实结果；未知结果标记执行状态未知，不谎称成功或回滚。恢复后的未完成工具批次必须经过历史校验/修复，使用准确的中断或未知结果记录补齐配对，然后等待用户新指令；绝不因缺少结果自动重放。持久化失败时不继续执行新的工具副作用。

## 7. 临时数据与 HTML 预览边界

临时工作区与 /tmp 是独立概念。后续临时工作区整个文件树使用临时存储，醒目标记不恢复；持久工作区内 /tmp 是与 /workspace 不同的挂载，默认不进入 ZIP，支持明确清空。不得劫持已有相对路径 tmp/ 目录而导致旧文件不可见，也不得把用户绝对路径传给宿主 OS。

当前临时探针 `.i/preview-probe.mjs` 在 Chromium/WebKit 中发现：同源 Service Worker + 不含 allow-same-origin 的 sandbox iframe 未得到虚拟 HTML 响应，实际落到静态服务器 404。此结果仅说明这个直接方案未成立，不证明所有浏览器虚拟服务方案不可行。

不能为让预览运行就把不可信生成页面与 Harness 同源执行。完整 HTML/CSS/JS 相对路径服务需要继续验证独立 origin 或安全资源桥接的架构及部署成本；涉及模块、fetch、资源路由和跨工作区隔离。未解决前本轮不承诺实现预览、不加载用户生成 HTML、不显示假服务启动成功。后续实现仍仅静态前端，不运行 Node/PHP 后端代码。

## 8. 验证与交付条件

先补回归：模型/名称 XSS、旧配置迁移、Remember/清凭据、PWA 控件和发布依赖、统一测试请求、自定义 Header 真实生效、取消、Native 会话路径及原子保存、trait 测试实现。

新增真实浏览器验收：
- 两个 Workspace 的同路径文件/图片/ZIP 不串，默认旧文件字节不变；同 Workspace 两个 Session 文件共享但模型 histories 不串。
- 刷新后恢复相同工作区、活动 Session、Tab 顺序、每会话输出/草稿/阅读位置；下一次请求包含恢复的真实上下文，而非仅恢复聊天外观。
- SSE 首段后刷新、审批中刷新、工具执行后 checkpoint 前故障、保存失败均不重复付费请求/工具；部分文字和未知结果正确标识。
- 新建/关闭/重开会话、切换工作区、连接缺失、数据库升级/损坏、配额拒绝和多窗口 revision 冲突可复现。

- PWA 离线重开能加载包括 i18n/本地高亮在内的完整静态依赖；管理数据与 key 不进入 Cache Storage；更新不混用 JS/WASM。

Node、Chromium、WebKit、共享 Rust 与 Native 定向回归需分别记录。既有四项网络失败与本轮新增回归分开，不宣称全仓库全绿。实际 iPhone、公网 HTTPS 部署、正式付费 key、插件安装不以自动化 mock 代替验证。
