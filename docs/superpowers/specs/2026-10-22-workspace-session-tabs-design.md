# 工作区、会话与终端标签页设计

状态：用户已确认概念与讨论中的布局；本文待用户审阅。此前 PWA/Stream 已交付，本轮尚未修改产品代码。

## 1. 用户目标与概念

用户同时需要共享文件的独立对话，以及文件完全隔离的项目，并希望页面接近终端：顶部 tabs，工具栏含 Download、Clear、New session、设置；正文优先显示终端。

- Workspace 是文件隔离边界，有稳定 ID、显示名称及独立 OPFS 根。
- Session 是对话上下文边界，绑定一个 Workspace，有独立 Agent 历史、终端输出、输入草稿、流式状态、审批及下载记录。
- Tab 是一个已打开 Session 的视图，不额外创造第三份会话状态。
- 同一 Workspace 可有多个 Session；不同 Session 不共享模型历史，同一 Workspace 的文件则立即共享。
- 全局配置共享 API URL/model/key、Stream、direct/relay、限制与 Remember。本轮不引入每工作区密钥覆盖。

采用单层会话 tabs + 明确工作区标识，不采用两个嵌套 tab 栏，也不让每个 Tab 强制拥有独立文件。这能满足两类需求且不改变用户确认的紧凑顶部布局。

## 2. 页面布局与操作归属

```text
[A · 开发网页 ×] [A · 检查代码 ×] [B · 分析数据 ×] [+]
----------------------------------------------------------------
工作区：A [切换] | Clear | New session | Download ZIP | 设置
----------------------------------------------------------------
当前会话终端输出 / 流式文字 / 当前会话工具审批

> 当前会话输入草稿                              [Cancel]
----------------------------------------------------------------
当前会话状态 · 模型 · 步数 · [Files]
```

工作区标识同时使用名称/短 ID 文本，不仅依赖颜色；active Tab 有明确视觉和 aria-selected 状态。手机 tabs 横向滚动，不挤压任务输入；按钮可换行，终端占主要空间。

| 操作 | 范围与语义 |
| --- | --- |
| 输入、Clear、New session | 当前 Session；Clear 仅清终端，不清历史/文件；New session 重置模型历史并显示分隔提示，保留文件与已有终端输出 |
| 审批、Cancel | 发起任务的 Session；按钮和描述同时标注会话、工作区，不允许批准另一个 Tab 的隐藏请求 |
| Files、Upload、Download ZIP | 当前 Session 所属 Workspace；工具 download 的结果链接归发起 Session |
| 设置 | 全局；任务运行中禁止改连接/模型配置 |
| 关闭 Tab | 关闭会话，不删除工作区文件；非空会话提示历史将丢失；活动任务必须先取消并结束，不静默杀任务 |

文件区默认折叠，显示当前工作区文件，包含 Upload 和工作区选择入口。设置改为可关闭的侧边抽屉，收纳完整配置、语言、PWA 安装/更新说明和 PC CORS 插件说明；支持 Esc 关闭、焦点返回与移动端滚动，不展示假安装成功。

## 3. 创建与切换

点击 + 打开两个明确选项：在当前工作区新建会话；新建工作区并新建会话。前者提示共享文件，后者要求名称并提示文件隔离。

工作区切换入口列出持久工作区；选定其他工作区时新建或激活其中一个已打开会话，不能直接把已有非空会话重绑到其他目录，防止历史里的路径和工具结果改变含义。

默认名称为工作区 1 / 会话 1 等；稳定身份由随机 UUID 决定，不把用户显示名称拼接到路径。支持编辑工作区/会话名称；名称去除首尾空白、非空且最多 80 字符，安全文本渲染。名称可重复，但同时显示短 ID 区分。

Tab 关闭后可从工作区列表重新开新会话，文件仍在。最后一个 Tab 关闭时在默认工作区新建空会话。本轮不提供工作区删除、复制或文件自动跨工作区移动，避免引入未经要求的破坏性操作。

## 4. OPFS 与旧数据兼容

现有 OPFS 根的 workspace/ 原样作为稳定 ID=default 的默认工作区；升级不搬迁、不删除、不复制其中任何文件。旧页面仍访问同一默认目录，不能因目录映射变化让用户误认为文件消失。

新工作区目录位于 OPFS 根 harness/workspaces/<UUID>/；管理元数据位于 harness/catalog.json，不属于任何模型可见 workspace。Agent 路径验证继续以选定根为边界，不能通过 ..、绝对路径或特殊 ID 访问其他工作区或 catalog。

catalog 只保存版本、工作区 ID/名称/创建时间，不含 key、模型历史或用户输出；更新以可关闭的 OPFS writable 写入，成功持久化后才报告新建成功。目录与元数据不能原子跨文件提交：先写目录再更新 catalog，失败时不显示成功、不清掉旧 catalog；启动可识别合法 UUID 孤立目录并以恢复名称列出，不删除或静默隐藏其中文件。

catalog 缺失时仍识别默认工作区，并扫描管理目录的合法 UUID 子目录恢复列表；损坏时给出明确恢复提示，不重置文件。仅检索 Harness 管理目录，不扫描无关 OPFS 数据。

BrowserAgent 增加显式绑定工作区的创建接口；保留原 create 的默认工作区行为兼容已有测试/调用。每个 Session 拥有独立 Agent 实例，所有工具、上传、列表、图片与 ZIP 均通过其固定根执行。工作区 ID 校验在 Rust/JS 边界均执行，不信任目录名或模型输出。

## 5. 任务、事件与并发

首期当前应用窗口同一时间只运行一个任务（跨所有 Workspace）。运行时可切换查看其他 Tab，但不能在其他会话发起任务；提示具体正在运行的会话。文件上传、ZIP 导出等与活动任务互斥，以免导出半写文件。

同一 origin 的不同浏览器窗口使用 Web Locks 对工作区任务/上传/导出加独占锁；不支持 Web Locks 时文件访问任务失败并明确说明，不能假装已避免跨窗口并发。不同工作区根仍隔离。全局模型配置在任务开始时取快照，其他窗口修改不会改变已发出的任务。

回调闭包绑定 sessionId/workspaceId，流事件还验证 requestId。切换 Tab 不改变请求、审批、文件副作用或下载归属；DOM 根据当前会话状态渲染，不能把旧流节点写入新 Tab。运行中的 Tab 显示进行中标记，后台审批显示待审批标记，用户切回该 Tab 后才能操作。

Cancel 只作用于当前 Tab 自己的活动请求；查看其他 Tab 时禁用该 Tab 的 Cancel，并提供跳回运行会话的入口。关闭活动 Tab 必须先明确取消并等待任务停止，然后确认是否关闭，迟到事件不得污染新建 Tab。

同一工作区文件变化后，返回其他 Session 时刷新文件区；历史消息不自动改写，不声称对话与最新文件快照完全同步。

## 6. 持久化与配置

Workspace 文件和 catalog 持久化。Session 历史、终端、草稿和打开的 tabs 在本轮保持页面内存态，与既有刷新行为一致；关闭/刷新或 PWA 更新会清会话，界面明确说明，并在有非空会话的更新/关闭 Tab 操作前提示。浏览器关闭提示仅尽力而为，不承诺拦截手机系统终止。

全局配置沿用 localStorage version=2 与显式 Remember，不因 Tab 功能偷偷持久化对话或 key。Clear configuration 清理所有已打开 Agent 的活动配置/历史与全局表单，不删 Workspace、catalog 或终端显示；有任务时禁止清理。未勾选 Remember 时不保存 API 配置。

catalog 名称、任务文本和模型输出均为不可信数据，使用 textContent；不加入 Service Worker 白名单，不进入其他工作区 ZIP。默认 ZIP 文件名可保留 workspace.zip，下载链接旁明确标注工作区与会话，不能以相同文件名覆写其他会话的对象 URL 状态。

## 7. 验证与范围边界

1. 旧 OPFS 默认目录文件升级前后字节一致；创建两个 Workspace 写同路径不同内容，读/列表/图片/ZIP 互相隔离，非法 ID/路径失败。
2. 两个 Session 共享 Workspace 文件但请求 histories 不串；另一 Workspace 的请求与文件不同；配置默认共享、Remember/Clear 语义保持。
3. 首段 SSE 后切 Tab 再返回不丢输出；审批不能跨 Tab；取消/关闭/迟到响应不串状态，不执行半截工具；Clear 活动会话禁用。
4. 同一 Workspace 多浏览器窗口锁保护；目录/catalog 写失败不伪成功，孤立目录与损坏 catalog 可恢复，不清用户文件。
5. Tab 新建/关闭/改名/最后一个关闭、工作区切换、输入草稿、抽屉焦点/Esc、手机横向 tabs、无横向页面溢出均测试。
6. 保留现有 Node、Chromium、WebKit、共享 Rust 回归，覆盖 PWA 缓存更新和子路径。PWA 构建重新生成全量哈希；不缓存管理数据和会话。

真实 iPhone、付费模型、公网发布和自动安装浏览器插件仍不属于自动化已验证范围。本轮不改变 Native CLI 或已有四项继承网络测试失败。
